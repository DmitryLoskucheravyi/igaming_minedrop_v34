# Minedrop

Одна ставка = до **7 спроб** на вертикальній рулетці. З кожної спроби випадає або **кірка**, або **пусто** (Х). **Перша ж кірка зупиняє прокрути** — рулетка їде вгору, поле піднімається, і кірка летить у нескінченну шахту на 8 колонок. Не випало за всі 7 — ставка згоріла.

Кірка б'є блоки, **відскакує й перевертається** (тому летить по діагоналі). Земля, камінь і динаміт падають з одного удару; **руда розколюється поступово** — тріщини наростають, як у майні. Політ триває, **поки не скінчиться HP**.

Відкривати: просто **`index.html`** у браузері. Ніякого білду/сервера не треба.

## Правила

| | |
|---|---|
| **Рулетка** | До 7 спроб по 0.62с. Шанс кірки ~16% за спробу → кірка є в ~70% ставок. |
| **Рівень кірки** | Дає **HP** (100 → 400) і **урон** (1 → 7). HP = скільки ударів витримає, урон = як швидко довбає руду. На суму виграшу рівень **не** впливає. |
| **Розкол** | Блок має міцність. Земля/камінь/динаміт — 1, вугілля 2, залізо 4, золото 6, алмаз 9. Кірка знімає свій урон за удар. Мідна (урон 1) довбає алмаз 9 разів, алмазна (урон 7) — двічі. |
| **HP над кіркою** | Піксельне сердечко + «40/100». |
| **Гроші** | Земля +2, камінь +4, вугілля +8, залізо +16, золото +30, алмаз +60. Множиться на ставку. |
| **TNT** | Вибухає 3×3 — сусідні блоки розносить одразу й безкоштовно. Сам коштує 20 HP і підкидає кірку. |
| **Верстак** | +1 рівень кірки і повне відновлення HP. Вмикається `_magic` скін. |
| **Х-блоки** | Множать **уже накопичений** виграш. Зароблене після них цим множником не іксується — тільки наступними. **x2 58% / x3 26% / x5 11% / x10 4% / x15 1%** (E = 3.04). Трапляються і в звичайній шахті, і в бонусній. |
| **Історія** | Колонка зліва: останні 12 ставок з іконкою і множником. |

## Бонусна гра

Рулетка сама крутить **15 разів**, і скільки кірок випало — стільки й **падає в шахту одночасно**, у спільний рахунок. У бонусній рулетці «пусто» важить менше і кірки зміщені до вищих рівнів — виходить **~11 кірок** за бонуску.

Щільність Х-блоків у бонусній шахті майже така сама, як у звичайній (`multWeight` 0.3 проти `multWeightBase` 0.25). Різниця в кількості спійманих множників (1.4 проти 0.13 за забіг) береться не зі щільності, а з того, що копає 11 кірок замість однієї.

Два способи потрапити:
- **Стрік** — кірка випала N ставок підряд. **Не перериває поточну ставку**: та догравається до кінця, показує свій результат, і аж тоді стартує бонуска.
- **Купити** — за `bonus.buyCost` ставок (зараз x70).

> ⚠️ **Стрік = 12, а не 3.** Ти просив 3, але це математично неможливо: кірка є в ~70% ставок, тому «3 підряд» спрацьовує **раз на 6 ставок**, а бонуска ціною x70 давала б RTP понад 1000%. При 12 вона спрацьовує раз на ~225 ставок і все сходиться.
> Хочеш саме 3 — тоді треба одне з двох, обидва в один рядок конфіга:
> - `bonus.buyCost: 6` — бонуска стає дешевою і слабкою (вартує ~x6);
> - `nothingWeight: 580` — кірка випадає в ~17% ставок замість 70%, і стрік-3 стає рідкісним.

## Файли

| файл | що робить |
|---|---|
| [config.js](js/config.js) | **усі цифри гри**: кірки, блоки, множники, рулетка, бонуска, фізика, глибина, скіни |

| [run.js](js/run.js) | **фізика забігу** — падіння, відскоки, розкол, HP, TNT, верстак, множники. Тримає масив кірок, тому бонуска = той самий код |

Фізика рахується **в клітинках, не в пікселях** — гра однаково поводиться на будь-якому розмірі вікна, і `run.js` ганяється в node без браузера.

## Баланс і тести

```
node sim/smoke.js           # інваріанти фізики (тріщини, множники, стінки, NaN)
node sim/headless.js 120    # САМА гра у фейковому DOM: рулетка, стрік, бонуска, купівля
node sim/final.js           # ГОЛОВНИЙ: RTP + payoutK + bootstrap CI + аналіз стелі
node sim/balance.js 15000   # розбивка RTP по кірках і розподіл виплат
node sim/cap.js             # окремий аналіз стелі виграшу
node sim/multtest.js        # порівняння варіантів таблиці множників
node sim/tune.js            # підбір стріку
node sim/tune2.js / tune3.js  # підбір tierBoost / reelNothing під ціну бонуски
```

Поточні цифри (40 000 ставок + 15 000 бонусок, `payoutK = 610`):

```
RTP разом 95.0%   (звичайна гра 62.4%, бонуски за стрік 32.6%)
кірка в 70% ставок | 30% ставок без кірки
політ: 28 рядів, ~64 блоки, ~16с
бонуска: раз на ~211 ставок | ~11 кірок | ~55с
куплена бонуска: E = x68.7 (95% CI x64.7..x73.0) за ціни x70 -> RTP купівлі 98% (CI 92..104%)
  медіана x19 | 90% x108 | 99% x912 | окупають ціну 15.8% бонусок
розподіл ставки: 30% нічого | 43% <0.5x | 13% 0.5-1x | 8% 1-2x | 5% 2-5x | 1% 5-20x
```

### Стеля виграшу — важливе застереження

`maxWinX = 5000` спрацьовує раз на ~940 бонусок (0.107%), але **зрізає 10.9% віддачі бонуски = 3.97 п.п. загального RTP**. Тобто стеля — не запобіжник, а несуча конструкція балансу: 0.1% подій тримають ~4% RTP.

Наслідки, про які треба знати:
- **Оцінка RTP крихка.** E[бонуска] має важкий хвіст, тому одна цифра нічого не варта — `sim/final.js` рахує bootstrap-CI. На 15 000 бонусок інтервал ще ±6%. На 4 000 зразках той самий конфіг давав то «кеп зрізає 3%», то «32%».
- **Прибирання x25/x100 хвіст майже не вкоротило** (було ~4.4 п.п., стало 3.97). Хвіст будує **кількість** множників, а не їхній розмір: при `multWeight = 1.0` кеп зрізав 85% віддачі, а звичайна гра падала до 7.9% RTP. Саме тому `multWeight` тримається на 0.3.
- Якщо треба, щоб стеля стала справжнім запобіжником — правильний хід не крутити `maxWinX`, а обмежити сам ланцюг (`Run.multChain`) явним максимумом. Це зробить хвіст обмеженим за побудовою, а не зрізаним постфактум.

Коли стеля спрацьовує, UI пише «СТЕЛЯ ВИГРАШУ x5000» замість показаного множника — інакше гравець бачив би `X3000` і виплату x5000 і читав це як обман.

### Головні ручки

| ручка | що робить |
|---|---|
| `payoutK` | RTP. Береться з `sim/final.js` (610) |
| `maxWinX` | стеля виграшу (5000). Несе ~4 п.п. RTP — див. застереження вище |
| `nothingWeight` | 84 проти 16 у кірок. Більше — рідше кірки |
| `bonus.streak` / `buyCost` | коли дається бонуска і скільки коштує. **Зв'язані** — див. попередження вище |
| `bonus.reelNothing` / `tierBoost` | скільки й яких кірок у бонусці |
| `bonus.multWeight` / `multWeightBase` | частота Х-блоків у бонусній / звичайній шахті |
| `bonus.multTable` | які саме ікси і з якою вагою |
| `TIERS[*].hp` / `dmg` | міцність і урон кірок |
| `BLOCKS[*].tough` / `cost` / `value` | міцність блоку, HP за удар, гроші за розкол |
| `manualAim` | `true` — гравець сам клікає колонку (зараз випадкова) |
